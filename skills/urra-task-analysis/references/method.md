# 从用途拆到具体动作

从目标用户开始任务时的状态推演到所需结果：物件在哪里、是否可直接使用，或屏幕正显示什么？每次交互从上一步留下的状态出发。例如，下一步要用袋内的物件，先还原用户怎样打开包装、取出物件；若物件已装入设备，就从装好后的状态开始。保留资料给出的顺序、对象和限制。资料简略时按已有功能选用一致的工作假设；若假设会改变操作链，在关联依据中写明受影响的动作。医疗阈值、剂量等产品专用参数只使用明确来源。

**使用目的按用户最终要取得的结果归组。** 从产品用途和本次范围确定用户为什么使用它。把共同实现这个结果的关键任务归入同一目的，在组内沿实际操作顺序展开。例如，用扫描仪“取得纸质文件的电子副本”，可以先后涉及装入原稿、设置扫描、保存文件；用户另有“将副本交给同事”的需求时，才单列交付目的。一个目的也可能只需一个任务。

**关键任务按可独立完成的阶段结果划界。** 给每个任务起一个能说明“做成什么”的名字。判断相邻操作是否分属两个任务时，看前一结果能否被独立使用、交付，或作为转做另一件事的起点。若它的意义只在于继续完成眼前同一件事，就把两段操作归入同一任务，即使中途换了部件、界面或操作人。

同一目标在不同地点或由不同角色完成，保留共同主线，在发生差异的动作处写明适用条件。异常、维护或交接若要求用户取得另一项结果，可在相应分支列任务；外部流程只分析与本产品交接的部分。

**按可独立做错的动作拆步。** 前一个动作做对，后一个仍可能被漏做或做错，并产生可区分的直接后果，就分成两步。例如，盒体已插到位仍可能漏扣卡扣，应分写“插入盒体”“扣紧卡扣”；若插入后自动锁定，则只写用户实际执行的动作。查找、辨认和判断同样可以独立出错，例如选对时段后仍可能读反曲线方向。同一动作的不同错误归在这一步。

**步骤名写准确的动词和操作对象。** 在“步骤”列直接写出用户怎么做。螺纹盖写“旋下保护盖”，已知要擦拭哪一面就写“擦拭探头表面”；软件操作同样写明对象，如“选择报告日期范围”。方向、位置、工具或按压方式会改变做法时一并保留，如“长按启动键”。识别线索、判断理由和完成反馈放在 PCA 中；若核对反馈本身决定下一步，则另列核对动作。动词的具体程度以资料或已注明的工作假设为依据：只知道要取盖时可写“取下保护盖”，不要擅自指定旋转方向。

**同行分析。** P 写当时可感知的线索，C 写使用者据此作出的理解或选择，A 沿用该步动作。使用错误落在本步可观察的偏差上：如已插入盒体但未扣紧，而非笼统写“安装失败”。原因写为何可能漏做，直接后果写产品或使用流程随即发生什么。环境或设备故障可以构成条件；分析其中由用户做错或漏做的动作。每个可区分的错误对应一条记录，保留同一步通过不同错误通向不同后果的情况。
