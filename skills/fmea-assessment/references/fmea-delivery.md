# FMEA 全量执行与续做

`RUN` 为本 Skill 的 `scripts/fmea-run.mjs` 绝对路径，`PROJECT` 为本次本地项目目录。固定命令已封装飞书读写和结构处理；正常路径无需临时编写脚本或加载完整 CLI 手册，异常时再查适用的 lark-* 说明。业务资料保存在项目目录，不放进 Skill 安装目录。

## 准备输入

根据用户指向区分评分对象和参考资料；多个链接不代表都要评分，明确的指定无需重复确认，无法确定目标子表、视图或问题列时只询问缺失信息。当前全量工具接受飞书 Base 子表/视图；普通表格（Sheets/Excel/CSV）、云文档、Word、PDF、图片等可作参考，不能直接传给 `prepare` 或冒充 Base 快照。用户只给了其他类型的评分对象时，说明当前支持的输入，请其确认包含问题记录的 Base 目标。格式不支持不等于内容没有问题；尚未读取时不判断是否存在问题记录。

```text
node RUN prepare PROJECT "用户提供的Base链接"
```

可选 `--field "问题列名或ID"`、`--name "项目名"`。身份顺序按 Skill 入口约定；仅在用户限定身份时传 `--identity user` 或 `bot`。

工具完整分页读取目标，保留原文、record ID 和视图顺序。问题列不唯一时返回候选，选定后对同一项目重跑准备命令。

执行返回的 `readCommand`，逐个窗口按 `nextCommand` 读至 `complete:true` 和 END 标记，核对摘要一致、位置连续。每次只返回一个窗口，输出预算须容纳它；工具截断时减小 `--max-chars` 重读该窗口。长单元格可跨窗口，不跳过后续内容，也不合并所有窗口打印。读取窗口仅用于完整传输资料，不划分评分任务。

随完整读取判断内容是否为产品使用问题；程序选中一个文本字段或完成导入，不代表内容适合评分。具体的使用困难、不舒适、害怕、理解障碍等也属于问题，不能因后果轻微而排除。普通产品介绍、操作说明、会议安排不能凭空改写成问题。

- **没有问题记录**：成功读取指定范围后，若只有介绍或说明等非问题内容，说明所读文件/子表、范围及内容性质，提示“未识别出可直接评分的产品使用问题记录，请确认评分文件或问题所在的子表/列”。不分派评分、不创建结果表。
- **混合内容**：说明哪些内容是问题、哪些是标题或说明；优先定位用户指定范围内已有的明确问题列/视图。当前工具会评分全部非空记录，不能仅让子任务漏评非问题行，也不能手改快照或项目绕过完整性检查。没有可直接使用的纯问题范围，或不同产品/版本无法区分时，向用户确认对应列/视图或请其提供只含待评问题的范围；范围明确后再准备输入，已绑定其他输入的项目使用新目录，不修改源表。
- **未能读取或读到空范围**：分别报告权限、文件格式、读取不完整或视图筛选等实际情况；不能将它们说成“文档没有问题记录”。

## 建立共享背景

多份参考资料在本环节整理，不另建评分阶段。资料较多或有读取缺口时，在项目目录简要记录各文件的链接/本地路径、用途、适用产品/版本（已知时）、已读范围和未采用/未能读取的原因；不要求固定格式，也不将这份清单塞给评分子任务。

飞书参考资料及附件仍经 CLI 读取或下载，本地文件按其格式使用当前客户端可用的工具。长文档先定位相关章节，再读取必要上下文；扫描件、图片、嵌入表格按需识别，核对会影响判断的文字、单位及表头。只能读取一部分、加密或无法识别时保留该限制，不声称已全文参考。无关或重复资料无需反复读取，不要求用户先把所有材料转成同一种格式。

实际用于判级的信息必须写入 `notes`：`text` 保留事实或明确的推断，`reason` 写明文件名/链接及页码、章节或记录位置，`appliesTo` 关联相关问题。产品画像识别出的必要使用条件也写入 notes，不另造字段。`references` 仅作引用归档，不传入评分任务；不能将判级所需事实只写在它的 summary 中。

型号、版本或情境不同的信息不可混用；说明书中的要求与观察到的实际操作分别保留，不能因二者不同就抹去问题记录。确有同一情境下的矛盾时，依据适用范围和来源核实；无法消解且妨碍有依据的判断时说明冲突并询问，不能静默择一当事实。普通资料缺失或不影响判级的未知按原标准处理，不一律阻塞，也不新增评分门槛。原始参考资料保留为可追溯来源，三个子任务继续共用一次整理后的关联背景。

依据 [产品画像要求](product-profile.md)，结合全部问题及现有补充资料，写一个背景 JSON：

```json
{
  "schemaVersion": 2,
  "inputHash": "prepare 返回的原问题快照摘要",
  "productName": "通用产品类别名称",
  "notes": [
    {"key":"report","kind":"fact","text":"相关产品条件","reason":"原记录或资料出处","appliesTo":[3,8]},
    {"key":"product","kind":"assumption","text":"适用于全部问题的产品条件","reason":"推断根据及未知条件","appliesTo":"all"}
  ],
  "references": [
    {"url":"实际采用的资料链接","summary":"采用的信息","appliesTo":"适用范围"}
  ]
}
```

只保留有助于本次判级的产品条件、必要未知及用户明确补充的情境；不逐条预评或提前固定每条问题的解释。事实使用 `fact`，经验推断使用 `assumption` 并注明根据，未知条件保持未知。确需解释原文歧义时，标明解释性质，不将其作为新增的确定事实。产品专用要求不能从其他品牌直接移植，也不能在背景中新增判级门槛或排除原规则允许的合理推断。

notes 的 key 唯一，没有补充内容可用空数组。按产品画像要求查证所需知识，只保留实际采用的资料；无外部来源可省略 references。

`appliesTo` 填 read-input 显示的固定快照行号数组，涵盖该条件可能影响的全部记录；真正适用于所有记录时才填 `"all"`。代码核对快照摘要并转换为稳定来源 ID 和 note ID。完整背景及引用归档，子任务接收背景条目与每条记录的关联 key。

```text
node RUN dispatch PROJECT profile.json
```

此命令生成三个任务，每份包含完整单维标准、关联背景、全部原记录及保存契约，并返回各自 readCommand。

## 子任务分派

实际启动三个并行子代理，分别负责 severity、occurrence、recovery，每个代理持续负责本维度全部记录。支持时使用不继承探索历史的最小上下文（如 `fork_turns="none"`），模型和推理档位沿用当前客户端；无并行工具时按维度依次完成。

给每个代理发送以下消息，仅替换读取命令：

```text
执行 <本维度 readCommand>，每次返回一个读取窗口，按 nextCommand 读至 complete:true 和 END_JOB，确认摘要一致、位置连续。若工具截断，减小 --max-chars 重读该窗口，不整文件打印或合并窗口。完整读取后按任务内的 instruction、原评分规则和 resultContract 完成评分与保存校验，返回结果路径、条数和完整性。
```

不附加其他维度分数、改写的判级口诀或逐条评分建议。专业自查按原标准执行，不另设全量 AI 复核任务，主代理不重新评分三份结果。

## 保存与合并

任务内提供 draftFile、saveCommand、checkCommand 和结果格式：

```json
{"contextHash":"任务文件中的值","rows":[["原记录ID",3,"支持该等级的关键依据"]]}
```

子代理通过指定命令保存。工具按 ID 合并，验证上下文、等级和理由，原子保存并保留历史；`checkCommand` 报告有效性、完整性及缺失 ID。错误只修复涉及的记录，不填默认分。程序校验不证明专业结论正确。

三个维度均完整有效后依次执行：

```text
node RUN accept PROJECT
node RUN publish PROJECT
```

`accept` 检查项目、背景、规则版本和完整 ID 集合，按原公式计算总分并生成九列结果。分类、原文映射和导出结构均由代码完成。

`publish` 在用户已授权的 Base 内新建结果子表，不发送消息或覆盖源表；按回执续做。云端每次至多写入200条是接口限制，与 AI 评分无关。工具核验图标和视图顺序，完整回读原文、等级、依据及总分，保存映射、基线和 `bindings/delivery.json`。返回完整验收通过后交付链接；程序回读不代表浏览器视觉检查。

## 续做和故障处理

```text
node RUN status PROJECT
node RUN check-scores PROJECT
```

按当前阶段复用同上下文的有效评分和已完成回执，只补缺失或损坏部分。分派后的输入固定，旧任务保留当时的规则与说明；新证据通过项目修订处理，不把旧评分直接用于新背景。

创建或写入结果未知时，先通过 CLI 核对回执和云端实际状态，不能直接重发、换身份或重建。权限与环境故障按 [CLI 故障处理](feishu.md#cli-故障处理)，保留已有进度。

未找到 CLI 时，先区分未安装与当前执行环境的路径不可见；确认未安装就提示用户先安装官方 `lark-cli` 并完成飞书接入，已安装则引导修复可执行路径。安装与授权方法查当前可用的 lark-shared/官方说明，不猜安装包或命令；不自动安装、登录或索取凭据。CLI 可执行但身份不可用时沿用 user → bot 的既有规则，能读取目标即继续。正常读取成功不另加安装或登录检查；只阻塞依赖故障的操作，已有本地资料和进度保留，修复后复测原目标并续做。

没有 fmea-run 项目状态的旧项目用 `assistant.mjs resume`。旧项目原有的全局背景关联不会自动收窄，需要时依据实际资料修改关联。

## 局部修订

`TOOL` 为本 Skill 的 `scripts/assistant.mjs` 绝对路径。先 `resume PROJECT`，按需读取相关记录，使用 `preview PROJECT patch.json`、`commit PROJECT patch.json` 保存补丁。结构仅需查 [数据契约](workspace.md#数据契约) 中的 issues、notes 及 [补丁与反馈](workspace.md#补丁与反馈)；其中 URRA 字段和导入流程不适用于 FMEA。

按相关完整评分标准修订指定记录及维度，保留其他评分、原文和 ID。改背景时编辑项目中的 note，其 noteIds 关联会将相关问题标记 stale；只检查受影响记录。背景适用范围改变时，同补丁更新问题的 noteIds 并标记 stale，不能只改归档 profile.json。

FMEA 的验收和导出类型为 `fmea`，导出到新的本地版本目录：

```text
node TOOL validate PROJECT fmea
node TOOL export PROJECT fmea 新版本目录
```

总分由原公式自动重算。云端局部更新只读 [三方同步](feishu.md#局部同步和人工修改保护) 中适用于 Base 的要求，按 record ID 定位并保护人工修改，不使用 Sheets 合并操作或用 publish 覆盖旧结果。
